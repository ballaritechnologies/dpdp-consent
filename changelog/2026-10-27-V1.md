## [Unreleased] - 2026-10-27
### Summary
DPDP consent flow (Phase 2): itemised per-purpose notice, granular unbundled consent with nothing pre-ticked, Data Fiduciary and grievance contact on banner and panel, a persistent "Privacy choices" button so withdrawal is as easy as consent, English + Hindi + Kannada + Telugu + Tamil, a visible `DRAFT - REQUIRES LEGAL REVIEW` label until a notice is marked reviewed, and an accessibility pass.
### Added
- `@consenti/utils`: `DPDP_LABELS` / `resolveDpdpLabels()` (UI labels as data; per-site overrides via `dpdpa.labels`); `profileLocales()` and `withLocaleOverlays()`; hi/kn/te/ta overlays for `opt-in-dpdpa`.
- `@consenti/types`: `DpdpaConfig.grievanceOfficer`, `grievanceUrl`, `noticeStatus`, `noticeVersion`, `reopenControl`, `labels`; `DpdpLabels`.
- `@consenti/ui`: `dpdp/notice.ts` (DPDP notice block, DOM-built, https-only links), `dpdp/reopen-control.ts` (persistent "Privacy choices" button); the banner now carries the notice and purpose list for DPDP profiles.
- `@consenti/ui`: the embedded DPDP profile carries every shipped language, so the flow works in Indian languages without a server.
- `@consenti/ui`: the widget root gets `lang` (and updates `dir`/`lang` on locale switch).
- `@consenti/api`: `dpdpa` block validation on profile create/update (`validators/dpdpa.validator.ts`); dashboard Profile Editor fields for grievance officer, grievance page, notice version, "reviewed" and the persistent button; six dashboard locales.
- Tests: `apps/ui/src/__tests__/dpdp-flow.integration.ts` (data checks plus Playwright: all five languages, no pre-ticks, granular save, keyboard withdrawal, reload, reviewed/no-button, data-only language, axe scan) and `apps/api/src/__tests__/dpdp.integration.ts`.
- Docs: DPDPA page rewritten for the new flow; `apps/ui/README.md` "DPDP flow (India)"; `docs/legal-open-questions.md` Q-D1 to Q-D5.
### Changed
- `@consenti/utils`: the `opt-in-dpdpa` template now has five separate purposes (preferences was bundled into functional), reject is as prominent as accept, wording without compliance claims, and it is marked DRAFT.
- `@consenti/utils`: for `opt-in-dpdpa`, a pre-granted consent purpose is now a validation **error** (was a warning).
- `@consenti/utils`: India's locale hints include `kn-IN` and `te-IN`.
- `@consenti/api`: default-profile seeding includes every locale a group ships (was a fixed de/es/fr/ja list).
- `@consenti/ui`: default `--consenti-color-text-muted` is now `#5f6b7a` (5.4:1 on white) instead of `#949dab` (2.7:1, below WCAG AA), found by the new axe scan.
- `@consenti/ui`: the DPDP notice in the modal is translatable and no longer hard-coded English.
### Fixed
- `@consenti/ui`: DPDP visitors could see a purpose pre-ticked if a profile set `preGrant`.
### Breaking changes
None for existing sites. DPDP profiles saved from the old built-in template keep their stored categories; re-seed or edit them to get the five-purpose layout. Sites that relied on `preGrant` on a DPDP profile now get it ignored.
### Migration
Optional: in the dashboard, open each DPDP profile, fill in the new notice fields, and tick "reviewed" once your lawyer has approved the text.
