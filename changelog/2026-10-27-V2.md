## [Unreleased] - 2026-10-27
### Summary
DPDP consent checker (Phase 3): `consenti-scanner dpdp <url>` and `runDpdpCheck()` run the existing three-state scan plus DPDP probes and write a gap report (JSON + HTML) with severity and plain-English fixes. Runs fully on the local machine.
### Added
- `@consenti/scanner`: `src/dpdp/` (probe, pure rule engine `evaluateDpdp()`, HTML report, runner), eight checks: notice shown, tracking before choice, tracking after reject, pre-ticked/bundled consent, withdrawal control, grievance contact, Indian-language option, site usable without optional consent.
- `@consenti/scanner`: `dpdp` CLI command with `--probe-pages`; exits non-zero when gaps are found.
- `@consenti/scanner`: `visibleBannerText()`, `listPreferenceCategoryStates()`; Hindi, Kannada, Telugu and Tamil accept/reject/manage/save labels and banner keywords.
- `@consenti/scanner`: test script and 15 tests, including end-to-end runs against two fixture sites (`fixtures/dpdp/gappy`, `fixtures/dpdp/good`).
- `@consenti/browser-engine`: `CHROMIUM_PATH` env var to launch an already-installed Chromium.
- `@consenti/ui`: language switcher options show each language's own name (e.g. "हिन्दी") with a `lang` attribute, instead of the bare code. Found by running the new checker against the widget itself.
### Changed
- `@consenti/scanner`: CLI wording "not necessarily a compliance gap" → "not necessarily a gap".
### Fixed
None.
### Breaking changes
None. Sites with a custom locale switcher are unaffected; the built-in switcher's option text changes from codes to names.

None.
