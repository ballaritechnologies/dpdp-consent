## [Unreleased] - 2026-10-27
### Summary
Launch assets for v0.1 (Phase 4): new README with a Docker quickstart verified end to end, plain-English guides, roadmap, contributor and security policies, issue templates, a landing page with an environment-configured waitlist form, and a CI check against compliance-claim wording.
### Added
- Root `Dockerfile` that builds the server from this repository's source (upstream's `docker/Dockerfile` installs the npm package, which lacks Ijazat's changes); optional `--secret id=ca` for TLS-intercepting proxies; `.dockerignore`.
- `docs/dpdp-vs-gdpr.md`, `docs/regimes.md`, `docs/checker.md`, `docs/roadmap.md`, `docs/releases/v0.1.0.md`; upstream's README moved to `docs/upstream-readme.md`.
- `site/landing/`: static landing page (no cookies, no third-party requests) whose waitlist form posts to `WAITLIST_ENDPOINT` from the environment; tests in `site/landing/build.test.mjs`, run in CI.
- `scripts/check-wording.mjs` (`npm run check:wording`, run in CI): fails on "compliant", "certified", "legally valid" and compliance "guarantees" in user-facing text.
- Issue templates: checker result, translation review; security reports routed to private advisories.
### Changed
- `README.md` rewritten for Ijazat; `CONTRIBUTING.md` (Ijazat ground rules), `SECURITY.md` (private vulnerability reporting, accurate IP-hashing description), bug/feature templates, `CODEOWNERS` (@ballaritechnologies).
- `docker-compose.yml`: service `ijazat`, builds from source, requires `CONSENTI_DATA_SIGNING_HASH` (the server refuses to boot in production without it, so upstream's compose file could not start).
- `apps/docs`: compliance-claim wording replaced across guides, terms and licence pages.
- `apps/ui/README.md`: the UMD global is `Consenti`, not `ConsentiUI`.
### Fixed
- Docker quickstart: missing `CONSENTI_DATA_SIGNING_HASH` and an unwritable `/data` volume for the non-root user.
### Breaking changes
None for library users. Compose users: the service is renamed `consenti` → `ijazat` and needs `CONSENTI_DATA_SIGNING_HASH`.
### Migration
Set `CONSENTI_DATA_SIGNING_HASH` (any random 32-byte hex) before `docker compose up --build`.
### Removed
- `.github/FUNDING.yml` (it pointed at the upstream maintainer's sponsorship profile).
