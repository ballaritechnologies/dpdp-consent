## [Unreleased] - 2026-10-27
### Summary
Record-keeping (Phase 5): signed consent receipts for every decision, notice version history, a deletion-request inbox with due dates and an audit trail, purpose-based retention with a daily job, and CSV/JSON export, on all seven storage drivers.
### Added
- Schema v4: generic `entity_records` table (SQLite, PostgreSQL, MySQL; MongoDB collection; JSON file array) behind new `StorageAdapter` methods `putEntity`, `getEntity`, `listEntities`, `countEntities`, `deleteEntities`. Upgrades run automatically and only add the table.
- `ReceiptService`: one HMAC-signed receipt per consent write (`given`, `updated`, `withdrawn`, `expired`, `erased`) with per-purpose state, notice version, language and source; visitors identified only by a keyed hash of the visitor ID.
- `NoticeVersionService`: an entry per saved profile version (notice version, review status, SHA-256 of the profile JSON).
- `ErasureRequestService` and the public route `POST /v1/consent/:visitorId/erasure-request`: deletion-request inbox with due dates (30 days default), status transitions, history, optional consent erasure on completion.
- `RetentionService`: per-tenant policy (purpose expiry, receipt and closed-request retention, response period), daily run for every tenant, on-demand run with dry run.
- Admin routes: `GET /receipts`, `GET /notice-versions`, `GET|POST /erasure-requests`, `GET|PATCH /erasure-requests/:id`, `GET|PUT /retention/policy`, `POST /retention/run`, `GET /export/receipts|erasure-requests|notice-versions`; OpenAPI updated.
- Dashboard **Records** page (inbox, receipts, notice versions, retention), strings in all six locales.
- Event `consent:purposes_expired`.
- Docs: `docs/records.md`, docs-site guide `/guides/backend/records`, admin/public route and event references, `apps/api/README.md`; legal questions Q-P1 to Q-P4.
- Tests: `entity-records.integration.ts` (all drivers; PostgreSQL/MySQL/MongoDB when `CONSENTI_TEST_*_URL` is set), `records.integration.ts`.
### Changed
- `ConsentService` takes an optional receipt writer (last constructor argument); `update()` takes an optional receipt override. `ProfileService` takes an optional notice-version writer.
- The `consent:erased` audit entry keeps only a digest of the erased record (id, profile, version, timestamps) instead of the full record with the visitor's decisions.
