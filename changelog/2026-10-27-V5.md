## [Unreleased] - 2026-10-27
### Summary
Children's data hooks (Phase 6): a visitor who answers the age gate as under age gets no optional purposes until a parent's consent is verified and never the blocked ones (analytics and advertising by default), enforced in the widget and on the server; parental-consent requests are recorded and can be verified through a pluggable provider, the signed token, or staff in the dashboard. No identity verification is built in.
### Added
- `@consenti/utils`: `restrictConsentForMinor`, `purposesBlockedForMinors`, `DPDP_CHILD_AGE`, minor cookie status constants; DPDP labels `minorBlocked` and `parentalPending` in en/hi/kn/te/ta.
- `AgeGateConfig.blockedPurposes` (category IDs never granted to a child); consent cookie field `m` (child status); receipt field `minor`.
- Widget: `getMinorStatus()`, `checkParentalConsent()`, event `consenti:parentalConsentVerified`; the preferences panel shows locked purposes with a note; the parental-consent request sends the locale.
- `ParentalConsentProvider` interface (`compliance.parentalConsentProvider`), `MockParentalConsentProvider` (development only, refuses production), `ParentalConsentService` (requests stored as `parental_consent` entities, hashed visitor IDs).
- Routes: `GET /v1/consent/:visitorId/parental-consent`; admin `GET /parental-consents`, `PATCH /parental-consents/:id`. The request route returns `requestId`, `status`, `redirectUrl`, `message`; resolving the token marks the request verified.
- Dashboard: Records → Parental consent tab; DPDP age hint in the profile editor. Strings in all six locales.
- Docs: `docs/children.md`, docs-site guide `/guides/backend/children`, method/event/route/config references, both READMEs; legal questions Q-C1 to Q-C4.
- Tests: `children.integration.ts` (api), a browser test for the child flow in `dpdp-flow.integration.ts` (ui).
### Changed
- Profile validation: `ageGate` is checked (types, 1–120), and an enabled age gate on a DPDP profile must use `minimumAge` ≥ 18.
- `ConsentService` takes an optional minor-policy dependency (last constructor argument) and restricts a child's consent on create and update.

### Breaking changes
- Profiles with a malformed `ageGate` (e.g. a string `minimumAge`) are now rejected on save.
