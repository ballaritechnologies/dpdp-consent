## [Unreleased] - 2026-10-27
### Summary
Multi-site isolation, stage 2 of 3 (admin API): every admin route works on the site named by `?tenantId=`, checked against the user's allowed sites, and lookups by ID no longer reach another site's records. The dashboard gets a site picker.
### Added
- Dashboard: a **Site** picker in the header (when the user can see more than one site); the API client adds `?tenantId=` for the chosen site to every request.
- `allSitesOnly()` auth helper for resources shared by every site (users, roles, the list of sites).
- Tests: admin-API cases in `tenant-isolation.integration.ts` (site-limited user, API keys, templates, stats, sites list, users and roles, TCF).
- Locale key `layout.site` in all six dashboard locales.
### Changed
- Consents, visitors, audit log, stats, analytics, export, profiles, consent and UI templates, API keys and setup routes use the shared site guard (`?tenantId=`, allowed sites, site exists).
- Profile, export and setup routes use the chosen site's profile service.
- `GET /tenants` is open to any signed-in user and lists only their sites.
- TCF/GPP registration (server-wide) is read from, and only changed through, the `default` site.
### Fixed
- Stats routes had no site check, and `GET /stats/aggregate` showed every site.
- API keys could be created for any site through the body `tenantId`, and revoked, re-enabled or deleted across sites.
- Analytics trusted an unchecked `?tenantId=`.
- Consent and UI templates, and profiles, could be read, changed or deleted by ID through another site; a profile could reference another site's templates.
- A site-limited admin could create users with access to every site, widen their own `allowedTenants`, or change the shared roles.
- `GET /tenants` showed every site's name to site-limited users; site-limited users could create, rename or delete sites.
### Breaking changes
- Site-limited users (non-empty `allowedTenants`) can no longer list or manage users, change roles or manage sites, and must name their site with `?tenantId=` on admin calls (the dashboard does this).
- Admin calls naming an unknown site get `404`; a site outside the user's sites gets `403`.
### Migration
None for single-site servers. Multi-site: give user and role management to users with an empty `allowedTenants`.
